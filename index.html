Selected work

Production incidents and architecture decisions: what broke, what the metrics showed, and what changed.

Slow LLM responses: the vendor's fix targeted the wrong component

Situation
LLM responses were slow. The vendor had scaled the auth service from 1 to 10 replicas.
Evidence
An approved concurrency test (180 requests, 0 errors) and vLLM metrics showed the bottleneck was long-prompt prefill on a single GPU.
Decision
Serving a second model replica on GPU capacity measured as allocated but idle.

A recurring GPU-node outage traced to a silent NVMe hang

Situation
A production GPU node kept going NotReady until rebooted.
Evidence
A minute-by-minute timeline across Prometheus, kernel journal, and BMC logs traced the freeze to an NVMe disk hanging silently in RAID1 while multipath requeued I/O.
Decision
The vendor confirmed the evidence pack, hot-swapped the disk, and stuck-I/O alerts were added.

Monitoring a vendor-managed AI platform without installing agents

Situation
A vendor-managed GPU platform had to join central observability without installing host agents.
Evidence
Built a read-only Prometheus federation bridge over SSH using only the Python standard library and systemd.
Result
The platform joined central alerting, and ingested time series dropped from ~25,000 to ~1,900.

A domain-wide DNS move, decided on evidence

Situation
A domain-wide DNS cutover to Cloudflare required an engineering risk analysis and rollback plan.

NVIDIA persistence mode: what it changes for GPU containers

25 Nov 2026

When no process holds the GPU open, the driver can unload its state. The next CUDA call then pays an initialisation delay of a few seconds. Persistence mode keeps the driver state loaded so that delay goes away.

What it does and does not do

It shortens startup for the first process that touches the GPU, which matters for containers that start and stop often. It does not raise throughput or clock speeds. For that you look at power limits, clocks and cooling.

Turning it on

sudo nvidia-smi -pm 1   # enable
sudo nvidia-smi -pm 0   # disable
nvidia-smi              # look for Persistence-M: On

The -pm switch is the legacy method. NVIDIA now recommends running the nvidia-persistenced daemon (usually a systemd service), which keeps the setting across reboots and is the better choice on servers.

When it is worth it

Many short container jobs that each initialise CUDA, or interactive tools where the first call feels slow. For one long training job that starts once, the saving is a few seconds and rarely matters.

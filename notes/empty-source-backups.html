An empty source is not a successful backup

18 Nov 2026

After an object-storage rebuild, a nightly backup failed with zero objects at the source and triggered two critical alerts. While investigating, I found a deeper gap: under certain conditions, the backup job could treat an empty source as a clean run and report success.

I recreated the backup reader account, buckets, and access policies, then pre-copied two application buckets (~5.6 GB) and verified zero diff before running a manual backup to green. Once the alerts cleared, I opened a separate fix for the condition that allowed an empty source to pass.

A green backup job only proves the process exited cleanly; verifying object count and diff proves there is something to restore.
